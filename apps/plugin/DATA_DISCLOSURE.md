# Data disclosure — what leaves this plugin

This document and `cloud/OutboundPayload.kt` are kept 1:1. Adding a new wire
shape requires a new sealed subtype AND a new section here. The compiler and
the `:checkNoPlaintextUrls` / `:checkNoHttpServer` gates enforce that there
is no other egress path.

## §1 — `session.hello`

Sent once, on plugin startup, after consent + cloud-chat are both on.

| Field | Source | Why |
|---|---|---|
| `deviceKey` | RuneLite config (`osrsllm.deviceKey`), generated locally on first run | Lets the backend bill the correct customer without a username/password login. |
| `playerName` | `Client.localPlayer.name`, or null if logged out | Used to display "currently playing as …" in the dashboard; never used for identification. |
| `pluginVersion` | gradle `version` | For compatibility prompts when the wire schema changes. |
| `rsAccountType` | RuneLite `AccountType` enum name | Lets the assistant give accurate advice (e.g. iron man can't use the GE). |

## §2 — `chat.userMessage`

Sent every time the player presses Enter in the chat panel.

| Field | Source | Why |
|---|---|---|
| `sessionId` | client-generated nanoid | Groups turns into a conversation for billing + history. |
| `turnId` | client-generated nanoid | Lets the backend correlate tool results back to a turn. |
| `text` | the literal chat input | The player's message to the LLM. |

## §3 — `chat.statePreamble`

Sent immediately after `chat.userMessage` once per turn. This is the compact
game-state snapshot the assistant needs to answer.

| Field | Source | Why |
|---|---|---|
| `sessionId` / `turnId` | as §2 | correlation |
| `preambleJson` | a JSON document built locally from the player's `GameStateStore` snapshot, the event log tail, and a few RuneLite integration outputs (slayer, XP tracker, clue scroll, party) | Game state the assistant uses to answer accurately — described to the user in plain English in the consent dialog. |

The preamble contents are deterministic — generated by
`co.rowm.osrsllm.chat.HarnessContext.build(...)` — and contain only fields
that already appear in the in-game UI.

## §4 — `tool.result`

Sent in response to a backend-initiated tool call. The result is whatever the
local MCP tool produced (e.g. bank contents, GE prices). Tool inputs come
from the backend, so the surface is bounded by which tools the plugin
exposes.

| Field | Source | Why |
|---|---|---|
| `sessionId` / `turnId` / `toolCallId` / `toolName` | echoes the backend's request | correlation |
| `resultJson` | the tool's serialized output | the answer the assistant asked for |
| `isError` | whether the tool threw | lets the assistant retry or surface the failure |

## §5 — `chat.cancel`

Sent when the player aborts an in-flight turn. Contains only the IDs needed
to cancel the right turn on the backend.

## §6 — `session.heartbeat`

Sent on a low-frequency timer while the socket is open. Carries no game
data — only the session ID and an uptime counter. Lets the backend drop
abandoned sessions promptly so a paying customer isn't charged for sockets
they aren't using.

## What is NOT sent

- Anything from the player's filesystem outside the plugin's RuneLite config
  directory.
- Anything from the operating system clipboard, keyboard, or microphone.
- Any RuneLite credentials, JWS tokens, or session cookies.
- Anything from RuneLite plugins other than the explicit integrations the
  player has enabled (slayer, XP tracker, clue scroll, party).
